# AI 智慧心血管疾病風險預測與健康管理系統｜展示講稿與操作流程

## 一、30 秒專題介紹

大家好，我的專題是「AI 智慧心血管疾病風險預測與健康管理系統」。

這個系統不是單純做一個心臟病分類模型，而是把資料清理、AI 風險預測、使用者輸入、健康建議、健康追蹤、檢查成本效益與管理者儀表板整合成一個可操作的 MVP 健康管理決策支援系統。

系統使用 Cleveland Heart Disease Dataset 作為模型訓練資料。使用者可以在前台輸入自己的檢查資料，系統會即時產生 risk_score、目前狀態與健康管理建議。後續也可以記錄血壓、血糖、體重、運動與睡眠，作為趨勢追蹤與異常提醒。

需要特別說明的是，本系統只作為課程專題、健康風險評估與決策支援原型，不取代醫師診斷或正式臨床判斷。

---

## 二、系統定位

本系統定位為：

1. 健康風險評估原型
2. AI 預測與健康管理整合系統
3. 可展示的 Streamlit MVP
4. 商業分析與決策支援儀表板

不是：

1. 不是正式醫療診斷系統
2. 不會告訴使用者一定有病
3. 不取代醫師、檢查或臨床判斷

展示說法：

> 我把模型輸出的結果定位為「風險分數」與「健康管理建議」，而不是醫療診斷。這樣比較符合課程專題與決策支援原型的定位。

## 三、資料來源說明

本專題 MVP 階段使用 Cleveland Heart Disease Dataset 作為主要模型訓練資料。

整理後資料：

```text
data/processed/cleaned_heart_data.csv
```

SQLite 資料庫：

```text
database/heart_disease_project.db
```

模型使用核心欄位：

```text
age, sex, cp, trestbps, chol, fbs, restecg, thalach, exang, oldpeak, slope, ca, thal
```

目標欄位：

```text
target
```

其中：

```text
target = 0：資料中沒有心臟病紀錄
target = 1：資料中有心臟病風險紀錄
```

展示說法：

> target 是資料集中由 Cleveland 的 num 欄位轉換而來，用於模型訓練，不代表系統對使用者做正式診斷。

## 四、健康追蹤資料為什麼不放進模型訓練？

健康追蹤資料包括：

```text
血壓、血糖、體重、運動、睡眠、症狀備註
```

這些資料目前不直接加入 Cleveland 模型訓練，原因是 Cleveland 原始資料沒有這些欄位。

MVP 階段策略：

```text
Cleveland 資料 → 訓練 AI 風險模型
使用者輸入資料 → 即時風險預測
健康追蹤資料 → 趨勢圖、異常提醒、健康管理建議
```

展示說法：

> 我沒有硬把健康追蹤欄位放進模型，是因為原始訓練資料沒有這些欄位。這些資料在系統中被用來做健康管理與趨勢追蹤，比較符合資料一致性。

## 六、老師可能會問的問題與回答

### Q1：這個系統是在診斷心臟病嗎？

不是。本系統是健康風險評估與決策支援原型，輸出的 risk_score 是模型根據 Cleveland 資料學到的風險分數，不代表正式診斷。若使用者有症狀，仍需要諮詢醫療人員。

### Q2：為什麼用 Cleveland Heart Disease Dataset？

因為 Cleveland Heart Disease Dataset 是常見的心臟病機器學習資料集，包含年齡、性別、胸痛型態、血壓、膽固醇、心電圖、最大心率等欄位，適合做 MVP 階段的風險預測模型。

### Q3：為什麼健康追蹤資料不加入模型？

因為 Cleveland 原始資料沒有體重、每日血壓、運動、睡眠這些欄位。若直接加入模型，訓練資料與使用者資料欄位會不一致。因此目前健康追蹤資料用於趨勢圖、異常提醒與健康建議，不直接加入模型訓練。

### Q4：303 筆資料會不會太少？

303 筆資料對正式臨床模型來說確實不大，所以本系統定位為課程專題與 MVP 原型。重點是展示從資料處理、模型訓練、即時預測到健康管理儀表板的完整流程，而不是宣稱可以達到臨床診斷等級。

### Q5：三個模型是什麼意思？

三個模型指的是三種演算法：

```text
Logistic Regression
Random Forest
Gradient Boosting
```

不是只拿三筆資料訓練。系統會比較 Accuracy、Precision、Recall、F1 和 AUC，再選出表現較好的模型作為 MVP 使用。

### Q6：risk_score 怎麼解讀？

risk_score 是模型預測的風險分數，數值越高代表模型評估風險越高。系統會再根據閾值轉成目前狀態，例如穩定觀察、建議加強追蹤、建議優先諮詢醫療人員。

### Q7：檢查組合價格是真的嗎？

不是。成本效益頁面的價格是 MVP 模擬資料，用於展示不同檢查組合的成本與效益比較，不是醫院正式收費。

### Q8：這個系統的商業價值在哪裡？

商業價值在於把 AI 預測、健康追蹤與管理者儀表板整合起來，讓使用者可以知道自己的風險狀態與追蹤方向，管理者也可以看到整體使用者風險分布、追蹤紀錄與資源配置建議。

## 七、結尾講法

我的專題重點不是只做一個心臟病分類模型，而是把 AI 預測結果轉換成可以被使用者理解、可以被追蹤、可以被管理者查看的健康管理決策支援系統。

目前 MVP 已完成：

```text
資料整理
SQLite 資料庫
AI 模型訓練
使用者即時預測
健康建議
健康追蹤
歷史紀錄
成本效益展示
Streamlit 儀表板
GitHub 版本管理
```
